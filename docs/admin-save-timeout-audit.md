# Проверка сохранения работ — 11.11.2026

## 1. Запрос и путь

Кнопка «Сохранить» в `ProjectsEditor.tsx` выполняет PATCH
`/api/public/sb/rest/v1/projects?id=eq.<id>` (после изменения также `select=id`).
Браузер на sm-electric.ru обращается к своему домену; обработчик Nitro передаёт
запрос в REST API существующего backend. Используются publishable key и токен
текущего пользователя, права доступа не обходятся. Фотографии и видео загружаются
отдельно через Storage, после чего записываются project_images/project_videos.
Сохранение текстовой формы не загружает файлы.

## 2. Причина

Исходная строка TIMEOUT возникает в обработчике `/api/public/sb/$`, когда
AbortController прерывает обращение к backend через 15 секунд. Прерывание
может произойти до получения заголовков либо во время чтения ответа.
По одной строке нельзя установить причину: DNS, TLS, сеть, задержка backend
или обработка запроса. Конкретная причина исходного отказа НЕ установлена.

Во время проверки sm-electric.ru: `/`, `/admin`, существующая страница работы,
REST projects и auth health отвечали 200, REST за 1,39 секунды, auth health
за 0,58 секунды. Неудачный production PATCH повторить не удалось.
В доступных опубликованных журналах Lovable за последний час соответствующей
ошибки нет; это не журналы Node/Nitro на REG.RU. Доступа к журналам REG.RU нет.
На момент задания продолжается региональный инцидент Lovable Cloud
(https://status.lovable.dev); он является возможной, не доказанной причиной.
Подключения и инфраструктура не менялись.

Подтверждён отдельный дефект обработки ошибок: SDK возвращает обычный объект
с полем error, но без message, и админка показывала пустое уведомление.
Воспроизведён ответом 504/TIMEOUT до изменения; после изменения то же
воспроизведение показывает понятную ошибку, без нового успешного уведомления.

## 3. Изменения

- Сохранены existing URL, ключи, клиентский same-origin транспорт, права доступа,
  приватность bucket, структура и внешний вид админки.
- Прокси сохраняет лимит 15 секунд; записывает безопасные поля: request ID,
  метод, обобщённый endpoint, backend host, фазу, время и код сетевой ошибки.
  Не журналирует токены, query, тела, имена файлов и персональные данные.
- Ошибки 504 содержат message/code/request_id. Запись не повторяется автоматически.
- Сохранение требует возвращённую строку id; отказ/нулевой результат не считается
  успехом. Состояние кнопки сбрасывается также при исключениях.
- Ошибки фото/видео также читают обычные объекты SDK. Ошибка обновления обложки
  больше не игнорируется.
- Таймаут не доказывает отсутствие записи в базе: пользователю предложено
  обновить объект и проверить данные перед повтором.

## 6. Следующий шаг для исходного TIMEOUT

Для доказательства причины нужен журнал конкретного неудачного PATCH на REG.RU.
После установки этих изменений запрос получает x-request-id, а серверный журнал
показывает фазу и код (например ENOTFOUND/ETIMEDOUT). Это позволяет отличить
сбой сети от задержки ответа без смены ключей и без увеличения timeout.
При подтверждённом сбое Lovable Cloud повторить операцию после завершения инцидента,
сначала проверив, не сохранились ли данные при потерянном ответе.
