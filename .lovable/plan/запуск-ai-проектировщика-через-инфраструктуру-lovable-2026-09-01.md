# Запуск AI-проектировщика через инфраструктуру Lovable

## Суть проблемы

`designPanel` и `renderPanelImage` — серверные функции самого приложения. На домене
`sm-electric.ru` они исполняются в Vercel, где нет управляемого ключа Lovable AI,
поэтому запрос к AI Gateway падает. Дизайн, логика расчёта и всё остальное здесь ни при чём.

## Предлагаемый вариант: AI-реле на стороне Lovable

Оставляем весь код проектировщика как есть, но AI-запрос уходит не напрямую в
AI Gateway, а на стабильный адрес опубликованного Lovable-деплоя того же проекта,
где ключ уже доступен как управляемый секрет.

```text
браузер (sm-electric.ru)
  → server function designPanel (Vercel)      — авторизация админа через Supabase
    → POST project--<id>.lovable.app/api/public/ai-relay   — общий секрет в заголовке
      → Lovable AI Gateway (LOVABLE_API_KEY берётся из окружения Lovable)
```

Почему это безопасно:

- `LOVABLE_API_KEY` остаётся только в окружении Lovable, в Vercel его не будет и в браузер он не попадает.
- Реле принимает только два фиксированных сценария (текстовый расчёт и картинка щита), никакой произвольный промпт-прокси наружу не открывается.
- Доступ к реле закрыт отдельным общим секретом `AI_RELAY_SECRET` (сравнение в постоянном времени). Он не даёт доступа к AI-балансу напрямую, только к этим двум операциям.
- Проверка прав администратора через Supabase остаётся первым барьером, как сейчас.
- Оплата AI по-прежнему идёт через Lovable, никакого отдельного Google API-ключа.

Если функция запускается внутри Lovable (превью или опубликованный домен),
ключ виден локально и реле не используется — запрос идёт напрямую, как сегодня.

## Что изменится

| Файл / настройка | Изменение |
| --- | --- |
| `src/routes/api/public/ai-relay.ts` | Новый серверный маршрут: проверка `AI_RELAY_SECRET`, валидация тела (`kind: "design" \| "image"`), вызов AI Gateway с управляемым ключом, отдача ответа как есть |
| `src/lib/panel.functions.ts` | Только транспорт: вместо прямого `fetch` к gateway — общий помощник, который выбирает прямой вызов или реле. Промпты, модели, разбор JSON, повторы и тексты ошибок не трогаем |
| Секрет `AI_RELAY_SECRET` | Создаётся в Lovable (генерируется автоматически) |
| Переменные Vercel | Добавить только `AI_RELAY_SECRET` (то же значение) и `AI_RELAY_URL` со стабильным адресом Lovable-деплоя. `LOVABLE_API_KEY` в Vercel НЕ добавляем |

Не меняются: дизайн, админка, прайс, КП, PDF/Word, сметы, Supabase-схема, домен
`sm-electric.ru` и его редиректы.

## Порядок работ после подтверждения

1. Создать секрет `AI_RELAY_SECRET` в Lovable.
2. Добавить маршрут-реле и точечно изменить транспорт в `panel.functions.ts`.
3. Проверить реле запросом с корректным и с неверным секретом.
4. Передать вам значение `AI_RELAY_SECRET` и точный адрес реле, чтобы вы добавили две переменные в Vercel и передеплоили.

## Альтернатива (если не хотите второй деплой в цепочке)

Перенести домен `sm-electric.ru` на публикацию Lovable — тогда всё работает без
реле и без дополнительных переменных, но потребуется перенастройка DNS и отказ
от текущего Vercel-деплоя. Реле — менее инвазивный путь.
